Think of it this wayThe documents are the library. RAG helps the LLM find the right page when someone asks a question.

2. Chunk the text and create embeddings

Chunking splits documents into manageable passages. An embedding model turns each passage into a numeric vector that represents aspects of its meaning.

3. Store chunks in a searchable index

Each chunk is stored with its text, source metadata and vector. A vector database or search index helps find relevant passages later.

4. Ask a question and retrieve context

The question is compared with the indexed chunks. This simplified demo uses keyword overlap to illustrate relevance; real systems may use vector similarity, keyword search or hybrid retrieval.

5. Generate an answer using retrieved context

The LLM receives the question plus the retrieved passages. It uses those passages as context to formulate an answer. This simulator uses a rule-based mock answer, not a live LLM.
